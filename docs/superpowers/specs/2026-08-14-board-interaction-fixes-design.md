# Дизайн исправлений взаимодействия с доской

## Цель

Сделать перенос задач предсказуемым, дать точную вставку в любую позицию колонки и привести элементы управления к существующему стилю Taskflow.

## Решение

`TaskCard` перейдёт с `useDraggable` на `useSortable`, а каждая колонка получит `SortableContext` с вертикальной стратегией. Карточки и пустая область колонки будут drop-зонами. Обработчик drop определит целевую колонку и соседнюю карточку, затем одна функция переместит задачу и обновит её статус в текущем массиве. Формат localStorage не меняется: массив уже является источником порядка.

DragOverlay будет показывать только копию активной карточки; оригинал остаётся частью сортируемой раскладки. Отмена drag очищает активное состояние. Pointer sensor начнёт drag после 8 px, touch — после короткого удержания; KeyboardSensor будет использовать координаты sortable.

Кнопка статуса станет доступным кастомным dropdown с `role="menu"`: открытие кнопкой, выбор статуса мышью/Enter/Space, закрытие по Esc или клику вне. Меню действий «⋯» получит такую же поверхность, границу, тень и состояния hover/focus. Время будет оставлено в метаданных, но резерв справа под drag-handle исключит пересечение.

Dialog откроется с fade/scale. При закрытии он сначала проигрывает обратную анимацию, затем вызывает навигацию; `prefers-reduced-motion` отключает ожидание. CTA «Создать задачу» получит явный светлый цвет и в нормальном, и в visited состоянии.

## Проверка

- Unit: перенос в выбранную позицию и обновление статуса.
- Component: CTA содержит явный класс светлого текста, dropdown меняет статус, Esc закрывает меню.
- E2E: drop между карточками приводит к нужному порядку и переживает перезагрузку.
- Полный прогон: `pnpm build`, `pnpm test`, `pnpm lint`, `pnpm format:check`; ручная проверка 360/1440 px, Tab/Enter/Space/Esc, console и malformed localStorage.
