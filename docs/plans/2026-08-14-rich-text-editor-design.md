# Дизайн WYSIWYG-редактора описания задачи

- **Дата:** 2026-08-14
- **Статус:** утверждён пользователем
- **Область:** форма создания и редактирования задачи, вывод описания в карточке

## Цель

Заменить обычную `textarea` в форме задачи на визуальный редактор Tiptap. Редактор должен поддерживать расширенное форматирование, соответствовать стилю Taskflow, работать с клавиатуры и сохранять данные в существующий localStorage без изменения схемы `Task`.

## Принятые решения

### Редактор и зависимости

Используется Tiptap WYSIWYG со следующими прямыми зависимостями:

- `@tiptap/react` — React-интеграция и `EditorContent`;
- `@tiptap/pm` — обязательная ProseMirror-зависимость React-интеграции;
- `@tiptap/starter-kit` — базовые узлы, форматирование и история изменений;
- `@tiptap/static-renderer` — безопасный статический вывод JSON-документа в React.

Все Tiptap-пакеты должны быть закреплены точными совместимыми версиями. В проект не добавляется библиотека иконок: небольшие SVG-иконки панели остаются локальными компонентами.

Официальная React-интеграция Tiptap требует `@tiptap/react`, `@tiptap/pm` и `@tiptap/starter-kit`: [React installation](https://tiptap.dev/docs/editor/getting-started/install/react). Для карточек используется React static renderer, который принимает JSON-документ без экземпляра редактора: [Static Renderer](https://tiptap.dev/docs/editor/api/utilities/static-renderer).

### Формат хранения

Источник данных, ключ localStorage, Zod-схема и поле `Task.description: string` не меняются.

Новый формат строки:

```text
tiptap:{"type":"doc","content":[...]}
```

Правила преобразования:

1. Пустой документ сериализуется в пустую строку `''`.
2. Строка с префиксом `tiptap:` разбирается как JSON-документ Tiptap.
3. Строка без префикса считается старым обычным описанием и преобразуется в документ с одним абзацем.
4. Если JSON после префикса повреждён или не похож на корневой документ `doc`, интерфейс не падает: исходная строка выводится как обычный текст.
5. При сохранении отредактированной старой задачи описание переходит в новый формат.

Префикс выбран вместо эвристики «любая валидная JSON-строка»: старое текстовое описание может само выглядеть как JSON и не должно ошибочно интерпретироваться как документ.

## Архитектура компонентов

### Кодек описания

В `entities/task/model` добавляется небольшой модуль с чистыми функциями:

- распознать формат строки;
- безопасно разобрать документ;
- преобразовать старый текст в документ;
- сериализовать непустой документ с префиксом;
- вернуть `''` для пустого документа.

Кодек не читает localStorage и не зависит от React. Им пользуются и редактор формы, и отображение карточки.

### Редактор формы

Отдельный компонент в `features/task-form/ui`:

- создаёт Tiptap editor через `useEditor`;
- получает строковое `value` и callback `onChange`;
- преобразует входную строку кодеком;
- на `onUpdate` передаёт форме сериализованную строку;
- не перезаписывает содержимое редактора на обычном родительском ререндере;
- синхронизируется с новым внешним значением при переключении на другую задачу.

`TaskForm` подключает компонент через `Controller` React Hook Form. Правила валидации остальных полей не меняются; описание остаётся необязательным.

### Вывод в карточке

В `entities/task/ui` добавляется компонент статического описания:

- старый текст отображается как один безопасный абзац;
- новый документ передаётся `renderToReactElement` из `@tiptap/static-renderer/pm/react`;
- пустой документ не создаёт пустой визуальный блок;
- `dangerouslySetInnerHTML` не используется.

Это позволяет отображать форматирование без создания полноценного экземпляра редактора для каждой карточки.

## Возможности и интерфейс

Панель содержит:

- обычный абзац;
- заголовки H2 и H3;
- жирный, курсив, подчёркивание и зачёркивание;
- маркированный и нумерованный списки;
- цитату;
- встроенный код и блок кода;
- ссылку;
- отмену и повтор действия.

Каждая команда представлена локальной SVG-иконкой с `aria-label` и подсказкой. Активные команды подсвечиваются фиолетовым; недоступные кнопки получают `disabled`.

Редактор использует палитру, радиусы и фокус-стили Taskflow. Область текста имеет минимальную высоту 160 px. При большом содержимом она растёт до разумного предела, после чего появляется внутренняя вертикальная прокрутка. На 360 px панель переносится на несколько строк без горизонтальной прокрутки.

## Ссылки

Кнопка ссылки открывает компактную встроенную панель рядом с toolbar, а не системный `window.prompt`.

- Поле содержит placeholder `https://example.com`.
- Enter применяет ссылку.
- Esc закрывает панель и возвращает фокус в редактор.
- Кнопка «Удалить» снимает ссылку с выделения.
- Разрешены только протоколы `http:` и `https:`.
- Неверный адрес показывает локальную ошибку и не меняет документ.
- В карточке внешняя ссылка открывается в новой вкладке с `rel="noopener noreferrer"`.

## Клавиатура и доступность

- Tab последовательно проходит команды панели, поле ссылки, редактор и остальные поля формы.
- Enter и Space активируют кнопки toolbar.
- Esc закрывает панель ссылки.
- Фокус всегда заметен.
- Иконки не являются единственным доступным названием команды.
- Семантика заголовков, списков, цитат и кода сохраняется при статическом выводе.

## Стили карточки

Форматированное описание не должно раздувать карточку:

- H2/H3 получают компактный размер и отступы;
- списки имеют внутренний отступ, но не выходят за границы;
- длинные URL и код переносятся или прокручиваются внутри блока;
- цитата выделяется левой фиолетовой линией;
- вертикальные отступы между соседними блоками уменьшены относительно полноценной статьи.

## Ошибки и совместимость

- Старые задачи открываются и отображаются без миграции всего localStorage.
- Повреждённое описание не ломает форму или доску и не теряется молча.
- Некорректный JSON всего localStorage продолжает обрабатываться существующим репозиторием задач.
- Ошибка URL отображается только внутри панели ссылки и не мешает исправить остальные поля.
- Редактор не меняет значения формы сразу после инициализации без пользовательского ввода.

## Проверка

### Автоматические тесты

1. Кодек: пустая строка, round trip Tiptap JSON, старый текст, строка, похожая на JSON, повреждённый prefixed JSON.
2. Форма: ввод и форматирование создают сериализованное значение; пустой редактор отправляет `''`; существующий обычный текст доступен для редактирования.
3. Ссылки: допустимый URL применяется, недопустимый отклоняется, удаление работает.
4. Карточка: старое описание и форматированный документ отображаются; вредоносная/повреждённая строка не выполняется и не вызывает падение.
5. Регрессия: обязательные поля, dropdown и отправка формы продолжают работать.

### Браузерная проверка

1. Создать форматированную задачу и проверить карточку.
2. Открыть задачу на редактирование и проверить восстановление форматирования.
3. Перезагрузить страницу и проверить данные из localStorage.
4. Проверить старую задачу с обычным текстом.
5. Проверить размеры 360 и 1440 px, отсутствие горизонтального скролла и визуальные состояния toolbar.
6. Пройти интерфейс через Tab, Enter, Space и Esc.
7. Проверить консоль браузера.

Перед завершением запускаются `pnpm build`, `pnpm test`, `pnpm lint` и `pnpm format:check` с фиксацией полного результата в журнале сессии.
