# Taskflow

Taskflow — учебный frontend-проект: Next.js-лендинг и локальная React-доска задач. Мини-доска выбрана из frontend-раздела `homework.pdf`, потому что на ней проверяются состояния, persistence, drag-and-drop и клавиатурная альтернатива.

## Возможности

- пустая доска, девять демо-задач и ошибка обязательного названия;
- создание, редактирование, удаление, смена статуса и сортировка между карточками;
- WYSIWYG-описание задачи;
- localStorage с безопасным сбросом повреждённых данных;
- управление мышью, touch, Tab, Enter, Space и Esc;
- адаптивные состояния на 360 и 1440 px и поддержка `prefers-reduced-motion`.

## Требования

- Node.js 24.x (проверено на 24.16.0);
- pnpm 11.19.0.

## Установка и запуск

```bash
git clone https://github.com/kaydo228/taskmanager.git
cd taskmanager
pnpm install --frozen-lockfile
pnpm dev
```

- Лендинг: <http://localhost:3001>
- Доска: <http://localhost:5173/board>

## Переменные окружения

- `VITE_LANDING_URL` задаёт адрес лендинга для dashboard;
- `NEXT_PUBLIC_DASHBOARD_URL` задаёт адрес dashboard для лендинга.

Локально переменные не обязательны: по умолчанию используются порты выше.

## Проверка

```bash
pnpm build
pnpm test
pnpm lint
pnpm format:check
pnpm --filter @taskflow/dashboard exec playwright test
```

## Архитектура и данные

- `apps/landing` — маркетинговый лендинг на Next.js;
- `apps/dashboard` — Vite + React-приложение с React Router и слоями `app`, `pages`, `widgets`, `features`, `entities`, `shared`;
- `packages/shared/src/ui` — общие UI-компоненты;
- задачи хранятся только в localStorage под ключом `taskflow.tasks`; массив проверяется Zod, сервер и внешний API не используются;
- форматированное описание остаётся строкой в существующем поле `Task.description`, поэтому контракт хранения не меняется.

## Допущения и ограничения

Проект работает локально и не поддерживает сервер, аккаунты, синхронизацию между устройствами и совместную работу. Vite предупреждает, что dashboard bundle превышает 500 kB; сборка при этом завершается успешно.

История репозитория не содержит сохранённого наивного прогона до появления рабочей спецификации, настоящего дизайн-скриншота «до» с теми же данными и заполненной первой сессии: `sessions/session-1.md` остался исходным шаблоном. Эти пробелы не реконструировались задним числом.

## Что не сделано

- не сохранён исходный наивный прогон;
- нет доказуемого сравнения наивного и финального прогонов;
- нет аутентичной пары дизайн-скриншотов «до/после» с одинаковыми данными.
