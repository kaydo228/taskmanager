# Taskflow

Taskflow — учебный frontend-проект: Next.js-лендинг и локальная React-доска задач. Мини-доска выбрана из frontend-раздела `homework.pdf`, потому что на ней проверяются состояния, persistence, drag-and-drop и клавиатурная альтернатива.

## Возможности

- пустая доска, девять демо-задач и ошибка обязательного названия;
- создание, редактирование, удаление, смена статуса и сортировка между карточками;
- WYSIWYG-описание задачи;
- localStorage с безопасным сбросом повреждённых данных;
- управление мышью, touch, Tab, Enter, Space и Esc;
- адаптивные состояния на 360 и 1440 px и поддержка `prefers-reduced-motion`.

## Требования

- Node.js 24.x (проверено на 24.16.0);
- pnpm 11.19.0.

## Установка и запуск

```bash
git clone https://github.com/kaydo228/taskmanager.git
cd taskmanager
pnpm install --frozen-lockfile
pnpm dev
```

- Лендинг: <http://localhost:3001>
- Доска: <http://localhost:5173/board>

### Наивный прогон

Исходный короткий прогон сохранён отдельно в [`native_run`](native_run). Это самостоятельная версия без сборщика и зависимостей:

```bash
python3 -m http.server 4174 --directory native_run
```

После запуска откройте <http://localhost:4174>. Минимальные тесты прогона запускаются командой `pnpm --dir native_run test`.

## Переменные окружения

- `VITE_LANDING_URL` задаёт адрес лендинга для dashboard;
- `NEXT_PUBLIC_DASHBOARD_URL` задаёт адрес dashboard для лендинга.

Локально переменные не обязательны: по умолчанию используются порты выше.

## Проверка

```bash
pnpm build
pnpm test
pnpm lint
pnpm format:check
pnpm --filter @taskflow/dashboard exec playwright test
```

## Архитектура и данные

- `apps/landing` — маркетинговый лендинг на Next.js;
- `apps/dashboard` — Vite + React-приложение с React Router и слоями `app`, `pages`, `widgets`, `features`, `entities`, `shared`;
- `packages/shared/src/ui` — общие UI-компоненты;
- задачи хранятся только в localStorage под ключом `taskflow.tasks`; массив проверяется Zod, сервер и внешний API не используются;
- форматированное описание остаётся строкой в существующем поле `Task.description`, поэтому контракт хранения не меняется.

## Сравнение наивного и итогового прогонов

Наивный прогон — один экран на HTML, CSS и нативных ES-модулях. В нём можно создать задачу с названием и статусом, переместить её через обычный `<select>`, удалить и сохранить массив в localStorage. Повреждённый JSON сбрасывается в пустой массив, а три теста проверяют добавление, пустое название и смену статуса. Это рабочий минимальный прототип, но он не покрывает обязательные для выбранной темы 5–10 записей, полноценную структурную валидацию, drag-and-drop и клавиатурную альтернативу ему.

После спецификации проект стал двумя приложениями в Turborepo: Next.js-лендингом и React-доской. На доске появились девять демо-задач и достижимая из UI ошибка, Zod-валидация localStorage, создание и редактирование через модалку с WYSIWYG-описанием, кастомные dropdown, а также pointer, touch и keyboard drag-and-drop со вставкой между карточками. Проверка выросла с трёх тестов хранилища до unit/component и Playwright-сценариев для persistence, malformed JSON, двух ширин, фокуса и клавиатурного переноса.

Цена такого перехода тоже видна: итоговая версия заметно сложнее и требует Node.js, pnpm и сборки; Vite предупреждает о размере dashboard bundle. Спецификация дала не просто другое оформление, а проверяемые состояния, доступность и критерии приёмки, которых в коротком промпте не было.

## Допущения и ограничения

Проект работает локально и не поддерживает сервер, аккаунты, синхронизацию между устройствами и совместную работу. Vite предупреждает, что dashboard bundle превышает 500 kB; сборка при этом завершается успешно.

Наивный прогон предоставлен пользователем и сохранён в `native_run`, но добавлен в Git поздним отдельным коммитом, поэтому история репозитория сама по себе не доказывает, что он был сделан до спецификации. `sessions/session-1.md` остался исходным шаблоном. Эти исторические сведения не реконструировались задним числом.

## Что не сделано

- первый обязательный контекстный промпт не зафиксирован: `sessions/session-1.md` остался шаблоном;
- порядок «наивный прогон → SPEC → реализация» не подтверждается хронологией Git.
