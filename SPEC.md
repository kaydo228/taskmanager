# Спецификация

## Что делаем

Taskflow — учебный веб-проект в Turborepo: маркетинговый лендинг на Next.js и личный кабинет с мини-доской задач на React.

## Для кого и зачем

Для человека, которому нужен быстрый наглядный способ записывать небольшие задачи, видеть их статус и переносить между этапами работы без регистрации и сервера.

## Сценарии

1. Посетитель открывает лендинг и переходит по CTA в личный кабинет.
2. На пустой доске пользователь создаёт задачу с названием, описанием, приоритетом и сроком; задача сразу появляется в «Нужно сделать».
3. Пользователь редактирует задачу, переносит её между «Нужно сделать», «В работе» и «Готово» перетаскиванием либо клавиатурной альтернативой.
4. Пользователь нажимает «Загрузить демо-данные» и получает 8–10 задач для проверки заполненной доски; «Очистить доску» возвращает пустое состояние.
5. Пользователь отправляет пустую форму и видит понятную ошибку валидации; исправление названия позволяет сохранить задачу.
6. После перезагрузки данные остаются. Если localStorage содержит чужой или испорченный JSON, кабинет открывается пустым и не падает.

## Состояния

- Пустая доска: первый запуск или результат очистки; отображаются объяснение и CTA создания/загрузки демо-данных.
- Заполненная доска: созданные или демо-задачи отображаются в трёх колонках.
- Ошибка валидации: у обязательного поля названия есть текст ошибки и фокус на поле; задача не сохраняется.
- Состояние перетаскивания: видна зона назначения, а карточка не дублируется.

## Чего точно не делаем

- Регистрацию, авторизацию, сервер, API, облачную синхронизацию и аналитику.
- Подзадачи, исполнителей, комментарии, вложения, системные уведомления и совместный доступ.
- Экранов сверх лендинга, доски и маршрутов формы/редактирования задачи.
- CDN-скрипты и внешние данные во время работы приложения.

## Допущения

- Данные хранятся только в localStorage: это обеспечивает автономную демонстрацию без бэкенда.
- Ошибка валидации формы засчитывается как достижимое ошибочное состояние: она полезна продукту и не требует искусственной поломки хранилища.
- Для доступного drag-and-drop используется `dnd-kit`: он поддерживает мышь, touch и клавиатурные сенсоры без собственной сложной реализации.
- Интерфейс и документация проекта — на русском языке, потому что пользователь и задание русскоязычные.

Нет.

## Критерии приёмки

- [ ] В репозитории есть Turborepo с `apps/landing` (Next.js), `apps/dashboard` (Vite + React) и `packages/shared/src/ui` с переиспользуемыми компонентами.
- [ ] Кабинет следует FSD: присутствуют и используются слои `app`, `pages`, `widgets`, `features`, `entities`, `shared`.
- [ ] React Router открывает доску, создание задачи и редактирование задачи; React Hook Form валидирует обязательное название; Sileo показывает подтверждения действий.
- [ ] Создание, редактирование, перенос и удаление задачи изменяют доску и сохраняются сразу.
- [ ] Доска имеет три статуса: «Нужно сделать», «В работе», «Готово»; перенос доступен мышью/touch и клавиатурой.
- [ ] Пустое, заполненное и ошибочное состояния достижимы через интерфейс без изменения исходного кода.
- [ ] 8–10 демо-задач загружаются кнопкой, а очистка возвращает пустое состояние.
- [ ] При некорректном JSON в localStorage приложение не падает и показывает пустую доску.
- [ ] На ширинах 360 и 1440 px нет горизонтальной прокрутки, обрезания текста и наложения интерактивных элементов.
- [ ] Tab проходит по всем интерактивным элементам с видимым фокусом; Enter и Space активируют элементы; Esc закрывает диалог.
- [ ] Сборка, тесты и линтер проходят; на ключевых сценариях нет ошибок в консоли.
- [ ] Лендинг и кабинет используют смысловые Motion-переходы; `prefers-reduced-motion` показывает конечное состояние без анимации.
