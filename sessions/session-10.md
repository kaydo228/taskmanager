## Размышления

Симптом похож либо на неверный адрес между двумя dev-приложениями, либо на SPA-навигацию, которая пытается обработать внешний для dashboard маршрут внутри React Router. До исправления нужно воспроизвести переход, проверить фактический `href`, порты запуска и сравнить логотип с рабочими ссылками. Codebase knowledge graph для проекта не индексирован, поэтому после подтверждённой ошибки MCP используется разрешённый fallback по локальным исходникам.

Корневая причина подтверждена сравнением конфигурации и ссылки: лендинг запускается командой `next dev --port 3001`, а логотип dashboard содержит `href="http://localhost:3000"`. На порту 3000 проект ничего не поднимает, поэтому браузер ждёт недоступный адрес и визуально «не переходит». Нужно уточнить границу исправления: только согласовать локальный порт или также сделать URL настраиваемым для будущего размещения.

Пользователь выбрал рекомендованный вариант: URL лендинга задаётся через `VITE_LANDING_URL`, а локальный fallback совпадает с фактическим dev-портом `3001`. Рассмотрены ещё два варианта: жёстко заменить только порт (самый короткий, но снова ломается при публикации) и выводить адрес из текущего origin (ненадёжно, поскольку лендинг и dashboard — отдельные приложения). Минимальный дизайн меняет только источник `href` логотипа и добавляет один поведенческий regression-тест; React Router, зависимости и маршруты не затрагиваются.

Пользователь утвердил дизайн. Решение фиксируется отдельной спецификацией до реализации: единственная dashboard-константа читает `VITE_LANDING_URL` и использует фактический локальный порт `3001` как fallback; обычный `<a>` сохраняется, поскольку переход выполняется между двумя приложениями.

Пользователь подтвердил письменную спецификацию. Реализация разбита на один TDD-цикл исправления ссылки и отдельный финальный этап браузерной/репозиторной проверки; новые зависимости и вспомогательные абстракции не нужны.

Regression-тест добавлен до production-кода и ожидаемо упал: ссылка `taskflow.` имела `href="http://localhost:3000"` вместо `http://localhost:3001`; остальные 29 dashboard-тестов прошли. Это напрямую подтвердило гипотезу о несовпадении портов. Минимальное исправление добавляет рядом с `BoardPage` одну константу с `VITE_LANDING_URL` и локальным fallback, не меняя механизм навигации.

После исправления сфокусированный и полный dashboard-прогоны прошли по 30 из 30 тестов. Реальная браузерная проверка открыла dashboard на `localhost:5173`, подтвердила `href=http://localhost:3001`, выполнила клик и завершилась на лендинге с заголовком «Дела в движении, голова свободна». В консоли были только служебные debug/info сообщения Vite, Next и React DevTools — ошибок и предупреждений нет.

Первый запуск `pnpm dev` для проверки сообщил `EADDRINUSE`: оба требуемых порта уже обслуживались запущенными процессами проекта. Вместо остановки пользовательских процессов использованы существующие серверы. Полный gate прошёл: `pnpm build`, 30 dashboard- и 3 landing-теста, `pnpm lint`, `pnpm format:check`; сохранилось известное предупреждение Vite о chunk >500 kB. Дополнительный Playwright-набор прошёл 3 из 3. Он автоматически перезаписал старый PNG сессии 9, поэтому этот посторонний генерируемый diff восстановлен из текущего `HEAD` и не включён в задачу.
