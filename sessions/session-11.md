## Размышления

Запрос охватывает не одну функцию, а аудит всей сдачи. Сначала нужно извлечь и визуально проверить полный `homework.pdf`, затем сопоставить обязательные артефакты и критерии с фактическими файлами репозитория. До gap-list и согласования неоднозначных изменений код не меняется; сам PDF остаётся неизменным.

Все 22 страницы извлечены и просмотрены в PNG-рендере. Для выбранного frontend-направления обязательны три достижимых состояния, 360/1440 px, безопасное чтение localStorage, клавиатурная проверка и пара скриншотов дизайна «до/после». Общая часть дополнительно требует рабочий README, сохранённый наивный прогон, сравнение двух прогонов, независимый аудит и честное описание ограничений.

Сопоставление показало, что продуктовая часть в основном закрыта: SPEC и Часть II AGENTS заполнены, 9 демо-задач и ошибка формы достижимы через UI, Zod сбрасывает повреждённый JSON, присутствуют unit/e2e-тесты и снимки на двух ширинах. Репозиторий публично отвечает HTTP 200 без авторизации. Критические пробелы сдачи: README остался исходной памяткой курса; нет сохранённого наивного результата и сравнения; нет зафиксированного независимого аудита; нет пары «до/после» с одинаковыми данными. `session-1.md` остался нетронутым шаблоном. Последние артефакты нельзя восстанавливать как исторические факты задним числом: это нарушило бы прямой запрет PDF и AGENTS на выдуманный гладкий журнал.

Пользователь попросил закрыть всё, что возможно. Выбран честный восстановительный объём: переписать README под фактический проект; уточнить в Части II AGENTS порты, три состояния и условия вопроса при визуальных изменениях; создать матрицу требований с прямыми ссылками на доказательства и явными историческими пробелами; выполнить свежую приёмку и сохранить актуальные снимки. Ретроактивное заполнение `session-1.md`, выдуманный наивный прогон и переименование старых снимков отклонены как нарушение правил курса.

Пользователь явно разрешил отдельного reviewer-агента. Он получит только PDF, финальный кандидат репозитория и задачу проверить соответствие без истории текущей работы; находки будут сохранены дословно, затем каждая получит решение с обоснованием.

Пользователь утвердил полный честный вариант. Дизайн включает README, уточнение только Части II AGENTS, матрицу всех требований, свежую браузерную приёмку, независимый аудит и проверку README из публичного клона. Исторические пробелы остаются явно отмеченными; старые журналы и доказательства не переписываются.

Пользователь подтвердил письменный дизайн. План делит работу на сдаваемую документацию, воспроизводимые Playwright-доказательства, независимый чистый аудит и финальную проверку из публичного клона. Самопроверка добавила неизменяемый SHA Части I AGENTS и отдельный secret-scan, чтобы два важных запрета проверялись командами, а не обещанием.

Документация разделена на две аудитории: README даёт человеку чистый путь установки и объясняет продукт, а матрица связывает каждый критерий PDF с конкретным доказательством. В матрице промежуточные проверки помечены `частично`, даже если код выглядит готовым: статус станет `закрыто` только после указанной воспроизводимой команды. В SPEC изменены только флажки уже подтверждённых продуктовых критериев; пробелы процесса не смешиваются с поведением приложения.
